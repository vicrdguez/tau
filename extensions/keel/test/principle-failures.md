# Principle delivery failures

- An agent without the principle tool sees its index. An offered agent loses the index on a later render.
- Project names appear ahead of Keel's or in filesystem order. The index leaks bodies or a pull returns metadata instead of the body.
- A worker sees stale index text or a stale body after the principle file changes in its checkout.
- A worker rework input binds a subsequently edited policy body instead of the one pinned by its worktree effect.
- A path-bound project principle misses its fenced item, or binds an unrelated item. A role-only binding leaks to another role.
- Shape omits model-the-domain. Ordinary rework gets attack-the-premise even though no addressed thread survived. A surviving fix or diagnosis misses its triggered bodies.
- A verifier sees only role-bound project principles instead of every project description.
- A ruling silently cites an unknown or index-only principle, or a body delivered to another conversation. A worker cannot cite a body actually delivered or pulled.
- An obsolete delivery task gives citation credit despite never submitting its input. Replaying a pull counts it twice or returns different text.
- A malformed project file blocks reconciliation, hides the remaining catalog, or grants citation credit. Repair is invisible until restart.
- The verifier and owner receive a ruling stripped of the principles it cites.
- An unbound, paused or retired agent pulls a body (existing kernel author test).
