# One-item acceptance failures

- A precedent-following bug stalls for approval, sends a brief to the wrong worker, loses the ruling or failed-verdict thread, skips merge proof or full-set review, lands more than one commit, leaves verifier checkouts, changes main, or fails to close after accept.
- SIGKILL after durable publication but before the first verifier checkout loses or replays the publication; SIGKILL after trunk CAS but before its receipt starts a second review or landing, loses the hand-over, or changes main.

# Reviewed Mandate acceptance failures

- A precedent-setting request loses a Ground gap or contradiction, a seam, a numbered annotation or rider disposition between rounds; the redesigned rule is not shown again, the coordinator misses the approving note, or Encode, its cited principle, the verifier's project guidance, merge, landing or hand-over is skipped.
- SIGKILL after the owner answers rework but before the designer publishes loses the annotations, restores stale rider decisions, creates another review for the answered round, or lets a build start without approval.

Run these through the real workflow entry and agent tools in a temporary repository. Only the recovery scenarios need SQLite and child processes. All other lane failures belong at the cheaper lane or kernel seam.
